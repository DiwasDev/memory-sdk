# ADR-001: User profile, conflict resolver, and versioned memories

**Status:** Accepted (owner's decisions; coach only formatted them)
**Date:** 2026-10-16

## Decision 1: Add a user profile and metadata alongside search results

We build a user profile and keep metadata on each memory, and we send them to the model together with the search results.

**Why:** Regular vector search misses the user's preferences, so the reply feels generic. With the profile in the prompt, the reply is more personalized.

**Assumption:** A personal profile will improve the response. The prompt will carry more context than before.

## Decision 2: Run a conflict resolver before the write gate

A new memory is checked against existing ones before the write gate decides. If it conflicts, the old memory is invalidated and the new one becomes the valid one.

**Why:** We don't want two contradicting memories. People don't have static preferences.

**Assumption:** This reduces conflicting memories being appended.

## Decision 3: Version memories with `valid_from` and `valid_until`

When a memory changes, we don't overwrite it. We add the newer version and close the old one by setting its `valid_until`. The old version stays stored.

**Why:** Human preferences change over time, and we don't want to lose the earlier version.

**Assumption:** None stated yet.
